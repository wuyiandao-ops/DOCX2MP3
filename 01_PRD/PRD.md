## 1. 簡介

### 1.1 文件目的
本文件旨在詳細定義「DOCX 轉 MP3 專業轉換工具」的產品需求、功能範疇、技術架構及成功指標。本文件將作為開發團隊（前端、後端、QA）在開發最小可行產品 (MVP) 階段的唯一事實來源。

### 1.2 產品背景
隨著有聲書與數位學習市場的興起，使用者對於將文字轉換為語音的需求日益增加。然而，市面上現有的網頁 TTS 工具常面臨以下痛點：
1. **長文崩潰**：處理超過萬字的 DOCX 檔案時，瀏覽器或伺服器常因記憶體不足而當機。
2. **語音限制**：特定地區（如中國、台灣、美國）的 TTS 服務常因網路連線限制或防火牆導致無法穩定存取。
3. **讀音錯誤**：中文破音字（如「般若」讀作「波惹」）在自動合成中準確率低，缺乏使用者自定義校正機制。
4. **輸出繁瑣**：長文件轉檔後需手動切分與命名，效率低落。

### 1.3 產品願景
打造一個輕量、穩定且高度可自定義的網頁轉換工具，讓使用者能精確地將長篇專業文件轉化為高品質語音檔，並徹底解決區域連線與破音字讀音問題。

### 1.4 MVP 目標
*   實作穩定的 DOCX 內容解析功能。
*   整合 Edge TTS，支援 TW、CN、USA 三大服務端點手動切換。
*   開發智慧型長文分拆演算法（以 10,000 字為限）。
*   建立視覺化的破音字/詞彙替換管理介面。
*   支援瀏覽器本地儲存 (LocalStorage) 以保留使用者設定。
*   提供自動命名的 ZIP 批次打包下載功能。

## 2. 目標用戶

### 主要用戶
*   **內容創作者/Podcaster**：需要將撰寫好的稿件快速轉為語音素材。
*   **學生與研究人員**：需將長篇論文或報告轉為音檔，利用通勤時間聆聽。
*   **語言學習者**：針對特定地區口音（美語、普通話）進行聽力練習。
*   **視障或閱讀障礙人士**：輔助閱讀長篇 DOCX 文件。

### 用戶特徵
*   **技術能力**：一般。熟悉瀏覽器操作，但不一定具備技術背景。
*   **設備環境**：主要使用桌上型電腦或筆記型電腦。
*   **需求特點**：追求轉檔效率，對語音的自然度與正確性（特別是破音字）有高度要求。

## 3. 核心問題與解決方案

*   **核心問題 1：跨國服務器連線限制導致 TTS 失敗**
    *   **MVP 解決方案**：在 UI 提供「服務區域選擇器」（TW/CN/USA），讓使用者根據所在網路環境手動切換 Edge TTS 端點，確保連線穩定。
*   **核心問題 2：破音字或專有名詞朗讀錯誤**
    *   **MVP 解決方案**：建立「可視化替換表」，允許使用者自定義詞彙對（如：般若 > 波惹），在合成前執行全域文字替換。
*   **核心問題 3：超長文件導致網頁崩潰或合成失敗**
    *   **MVP 解決方案**：實作 10,000 字自動分拆邏輯，系統自動尋找最近的句號或換行符進行切分，分批合成音檔。
*   **核心問題 4：多個分拆檔案下載混亂**
    *   **MVP 解決方案**：自動執行檔案編號（_01, _02...）並透過 JSZip 進行前端打包，提供一鍵下載 ZIP 功能。

## 4. 產品功能 (MVP 範圍)

### 4.1 檔案上傳與解析模組
*   **功能描述**：負責接收使用者上傳的 DOCX 檔案並準確提取純文字。
*   **具體子功能**：
    *   **拖放上傳介面**：支援點擊上傳或將檔案拖入指定區域。
    *   **DOCX 解析器**：提取文字內容，忽略圖片、表格格式，保留基本的換行與段落。
    *   **字數統計顯示**：解析後即時於介面顯示總字數，並預告將分拆成多少個檔案。

### 4.2 視覺化替換表管理模組 (核心功能)
*   **功能描述**：提供使用者修正朗讀錯誤的直覺介面。
*   **具體子功能**：
    *   **詞條新增/刪除介面**：使用者可輸入「原始文字」與「替換後文字」。
    *   **即時列表顯示**：以表格形式條列所有替換規則，支援一鍵刪除。
    *   **本地記憶功能**：利用 LocalStorage 自動儲存清單，關閉瀏覽器後再開啟仍可保留。
    *   **匯入/匯出功能**：支援將替換表匯出為 JSON/TXT 檔，並能重新匯入。

### 4.3 語音合成配置模組
*   **功能描述**：設定 TTS 的聲音細節與連線路徑。
*   **具體子功能**：
    *   **服務區域選擇 (Region)**：選單包含台灣 (TW)、中國 (CN)、美國 (USA)。
    *   **人聲列表選單**：依據選擇區域，動態加載對應的語音（如曉臻、雲希、Guy）。
    *   **語速控制**：提供 0.5x 到 2.0x 的滑桿調整。
    *   **音高控制**：提供 -50Hz 到 +50Hz 的數值微調。

### 4.4 智慧分拆引擎
*   **功能描述**：處理超過字數上限的文字段落。
*   **具體子功能**：
    *   **臨界點掃描**：當字數達 10,000 字時，向後尋找最近的標點符號（。！？）或換行符。
    *   **段落完整性保護**：確保分切點不會落在句子中間，維持朗讀語感的連貫性。
    *   **任務佇列管理**：分批發送請求給 TTS 服務，避免瞬間連線過多被封鎖。

### 4.5 輸出與打包下載模組
*   **功能描述**：管理合成後的 MP3 檔案並交付給用戶。
*   **具體子功能**：
    *   **自動命名邏輯**：採 `[原檔名]_[序號].mp3` 格式。
    *   **進度條顯示**：顯示當前轉換進度（如：正在轉換第 2/5 個檔案）。
    *   **ZIP 打包系統**：在前端完成所有 MP3 的封裝，不佔用伺服器儲存空間。

## 5. 用戶故事

1.  **作為**一名文字工作者，**我想要**上傳 3 萬字的 DOCX 稿件，**以便**我能將其轉換成語音來校對文章節奏。
2.  **作為**一名佛教經文研究者，**我想要**將「般若」設定替換為「波惹」，**以便**在轉換 MP3 時朗讀音調正確。
3.  **作為**一名在中國出差的工程師，**我想要**手動切換連線區域至「CN」，**以便**繞過網路限制正常使用 TTS。
4.  **作為**一名使用者，**我想要**調整語速為 1.2 倍，**以便**節省聆聽長篇文章的時間。
5.  **作為**一名使用者，**我想要**一次下載所有分拆後的音檔，**以便**我不必手動點擊十幾次下載按鈕。
6.  **作為**一名經常使用的用戶，**我想要**程式記住我上次填寫的替換表，**以便**我每次轉換時不需要重複輸入。
7.  **作為**一名美語學習者，**我想要**選擇美國地區的語音端點，**以便**獲得最道地的美式英語發音。
8.  **作為**一名使用者，**我想要**在轉換時看到進度條，**以便**我知道還需要等待多久。

## 7. 技術要求

### 7.1 後端框架：Node.js (Express 或 NestJS)
*   **理由**：Node.js 對非同步 I/O 處理極佳，適合處理多個 TTS 請求的佇列。且有成熟的 `edge-tts` 社群實作庫。

### 7.2 資料庫：不適用 (MVP 階段)
*   **理由**：為了保持輕量化與隱私，MVP 不存儲使用者文件，替換表存於前端 LocalStorage。

### 7.3 資料庫 ORM：無

### 7.4 前端技術：React.js + Tailwind CSS
*   **理由**：React 適合開發複雜的狀態管理（如替換表編輯），Tailwind 能快速構建響應式且簡約的介面。

### 7.5 其他整合
*   **DOCX 解析**：使用 `mammoth.js` 進行前端文字提取。
*   **TTS 橋接**：使用 `edge-tts` 或自建 Proxy 伺服器轉發請求至 Edge 伺服器，並處理區域切換。
*   **打包工具**：使用 `JSZip` 與 `FileSaver.js` 實作前端下載。

### 7.6 部署環境：Docker + AWS 或 Vercel
*   **理由**：確保後端連線端點穩定，建議部署於具備全球加速功能的雲平台。

### 7.7 版本控制：Git (GitHub/GitLab)

## 8. 成功指標

*   **轉換成功率**：長度超過 50,000 字的文件轉換成功率需達 98% 以上。
*   **連線穩定度**：在切換正確區域的情況下，TTS 連線超時率低於 2%。
*   **處理效率**：10,000 字的文字轉換並產出 MP3 的時間應控制在 60 秒內（視網路狀況）。
*   **用戶留存**：透過 LocalStorage 觀察替換表重複使用率（二次訪問比例）。
*   **正確性回饋**：核心用戶反映破音字問題得到有效解決。

## 9. 假設與約束

### 9.1 假設
*   使用者上傳的 DOCX 檔案未加密且未損毀。
*   微軟 Edge TTS 服務端點持續開放且免費使用。
*   使用者的瀏覽器支援現代 JavaScript API（如 Blob, LocalStorage）。
*   使用者有穩定的網路連線以進行大檔案下載。
*   法律合規性：假設使用者上傳之內容皆具合法授權。

### 9.2 約束
*   **瀏覽器記憶體限制**：單次處理的總字數上限暫定為 100,000 字，以防瀏覽器崩潰。
*   **連線限制**：受限於 Edge TTS 的頻率限制 (Rate Limiting)，可能需限制並發請求數。
*   **檔案格式限制**：僅支援 .docx，不支援 .doc, .rtf 或 .pdf。
